# TechDocs 코딩 및 주석 규칙

## 1. 목적

이 문서는 코드의 의도와 변경 이유를 빠르게 이해하고, 사람과 AI가 같은 기준으로 TechDocs를 유지하기 위한 규칙을 정의한다.

## 2. 이름 작성 규칙

- 변수명과 함수명은 역할이 드러나는 영어를 사용한다.
- 축약어는 프로젝트에서 널리 합의된 경우에만 사용한다.
- Boolean 값은 `is`, `has`, `can`, `should`처럼 상태를 알 수 있는 접두사를 사용한다.
- 함수명은 수행하는 동작이 드러나도록 동사로 시작한다.
- 이름만으로 의미를 설명할 수 있다면 이를 대신하는 주석을 추가하지 않는다.

## 3. 파일 상단 주석

직접 관리하는 주요 소스 파일의 최상단에는 파일 역할, 작성자, 최종 수정일 및 주요 책임을 작성한다.

### TypeScript 및 JavaScript

```ts
// ============================================================
// 파일 역할: 검색 API 요청과 스트리밍 응답 처리를 담당한다.
//
// 작성자: 심우현
// 최종 수정일: 2026년 8월 10일
//
// 주요 책임:
// - 검색 요청 생성
// - 스트리밍 응답 파싱
// - API 오류 변환
// ============================================================
```

### Python

```python
# ============================================================
# 파일 역할: 검색 결과를 결합하고 최종 순위를 계산한다.
#
# 작성자: 심우현
# 최종 수정일: 2026년 8월 10일
#
# 주요 책임:
# - 벡터 검색 결과 수집
# - BM25 검색 결과 수집
# - RRF 기반 순위 결합
# ============================================================
```

### 적용 기준

- 작성자는 `심우현`으로 표기한다.
- 날짜는 `YYYY년 M월 D일` 형식으로 작성한다.
- 파일의 동작, 로직 또는 책임이 변경되면 최종 수정일을 갱신한다.
- 파일 책임이 달라지면 `파일 역할`과 `주요 책임`도 함께 수정한다.
- 단순 오탈자, 공백 및 포맷 변경에는 날짜 갱신을 생략할 수 있다.
- shebang이 필요한 스크립트는 shebang을 첫 줄에 두고 그 아래에 헤더를 작성한다.
- JSON, lock 파일, 자동 생성 파일, 외부 코드 및 주석을 지원하지 않는 파일에는 적용하지 않는다.

## 4. 로직 주석

- 주석은 필요한 경우 한국어로 작성한다.
- 코드가 무엇을 하는지 반복하지 말고, 해당 방식이 필요한 이유를 설명한다.
- 비즈니스 규칙, 예외 처리, 성능 최적화, 외부 API 제약 및 우회 구현에는 근거를 남긴다.
- 코드 변경으로 설명이 달라지면 주석도 같은 작업에서 수정한다.

좋은 예:

```python
# 검색 결과와 추천 결과에 동일 특허가 포함될 수 있으므로
# 출원번호를 기준으로 중복을 제거한다.
unique_patents = deduplicate_by_application_number(patents)
```

불필요한 예:

```python
# 카운트를 1 증가시킨다.
count += 1
```

## 5. 완료 기준

- 변경한 코드와 상단 설명이 서로 일치한다.
- 의미 있는 소스 변경에는 최종 수정일이 반영되어 있다.
- 오래되거나 코드와 충돌하는 주석이 남아 있지 않다.
- 관련 린트, 빌드 또는 테스트 결과를 PR에 사실대로 기록한다.
