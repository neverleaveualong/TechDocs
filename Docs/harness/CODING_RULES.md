# 코딩 및 주석 규칙

## 이름 규칙

- 변수명, 함수명, 클래스명 및 파일명은 의미가 드러나는 영어로 작성한다.
- Boolean 값은 `is`, `has`, `can`, `should`처럼 상태가 드러나는 이름을 사용한다.
- 함수명은 수행하는 동작이 드러나는 동사로 시작한다.
- 프로젝트에서 합의되지 않은 축약어를 사용하지 않는다.

## 파일 상단 주석

새로 만들거나 의미 있게 수정하는 직접 관리 소스 파일에는 파일 역할, 작성자, 최종 수정일 및 주요 책임을 작성한다.

### TypeScript 및 JavaScript

```ts
// ============================================================
// 파일 역할: 검색 API 요청과 스트리밍 응답 처리를 담당한다.
//
// 작성자: 심우현
// 최종 수정일: 2026년 8월 10일
//
// 주요 책임:
// - 검색 요청 생성
// - 스트리밍 응답 파싱
// - API 오류 변환
// ============================================================
```

### Python

```python
# ============================================================
# 파일 역할: 검색 결과를 결합하고 최종 순위를 계산한다.
#
# 작성자: 심우현
# 최종 수정일: 2026년 8월 10일
#
# 주요 책임:
# - 벡터 검색 결과 수집
# - BM25 검색 결과 수집
# - RRF 기반 순위 결합
# ============================================================
```

## 적용 기준

- 작성자는 `심우현`으로 표기한다.
- 날짜는 `YYYY년 M월 D일` 형식으로 작성한다.
- 로직, 동작 또는 파일 책임이 변경되면 최종 수정일을 갱신한다.
- 파일 책임이 달라지면 파일 역할과 주요 책임도 함께 수정한다.
- 단순 오탈자, 공백 및 포맷 변경에는 날짜 갱신을 생략할 수 있다.
- shebang이 필요한 스크립트는 shebang을 첫 줄에 두고 그 아래에 헤더를 작성한다.
- JSON, lock 파일, 자동 생성 파일, 마이그레이션, 외부 코드 및 주석을 지원하지 않는 파일은 제외한다.

## 로직 주석

- 필요한 설명은 한국어로 작성하되 기술 용어와 라이브러리 이름은 원문을 유지한다.
- 코드가 무엇을 하는지 반복하지 말고 해당 구현이 필요한 이유를 설명한다.
- 비즈니스 규칙, 예외 처리, 성능 최적화, 외부 API 제약 및 우회 구현에는 근거를 남긴다.
- 코드 변경으로 설명이 달라지면 주석도 같은 작업에서 수정한다.
- 코드만으로 명확한 동작에는 불필요한 주석을 작성하지 않는다.

좋은 예:

```python
# 검색 결과와 추천 결과에 동일 특허가 포함될 수 있으므로
# 출원번호를 기준으로 중복을 제거한다.
unique_patents = deduplicate_by_application_number(patents)
```

불필요한 예:

```python
# 카운트를 1 증가시킨다.
count += 1
```
